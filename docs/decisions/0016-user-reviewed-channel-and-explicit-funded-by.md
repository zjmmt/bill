# ADR-0016：业务渠道由用户复核，银行卡证据以显式 FUNDED_BY 去重

- 状态：已接受
- 所有者：项目维护者
- 最后核验：2026-08-01
- 事实来源：项目负责人对缺通知场景的回退决定、ADR-0003、ADR-0009、ADR-0012、采集复核规格、对账设计与当前 Room v9 实现

## 背景

支付宝或微信内部支付、红包、转账等页面不保证产生系统通知。Bill 已能由快捷设置磁贴对当前一帧做本地 OCR，但该证据在来源层只能诚实标为通用截图；仅凭截图采集通道，无法知道业务实际发生在支付宝、微信或银行。现有 Draft 创建后又不能改金额、时间和商户，导致 OCR 误差无法完整复核，同一笔“钱包支付 + 银行扣款”也会形成两笔支出。

## 决定

### 证据来源与业务渠道分离

`RawEvent`、来源族、截图/通知类型和证据链接保持不可变。`ReviewDraft` 新增可审核的 `ObservedChannel`：`ALIPAY`、`WECHAT`、`BANK`、`OTHER`、`UNKNOWN`。它表达用户确认的业务发生渠道，不反向改写或夸大证据来源。

- 已识别的支付宝、微信、银行通知可以按来源预填渠道，用户仍可纠正。
- 通用截图 OCR 和普通手工录入默认 `UNKNOWN`；用户在审核页选择渠道后才参与跨来源匹配。
- 渠道名称和界面语言不是金额识别硬条件。简体中文、繁体中文和英文页面都以金额、货币与交易状态为主，文字别名只用于提高语义置信度。

### 无通知场景使用单帧、用户触发回退

平台不产生通知不是基础可用性的阻断项。用户可通过快捷设置磁贴只截当前一帧，在设备上离线 OCR，并立即进入可编辑审核；应用不后台轮询、不全天截屏、不保存原始像素。OCR 无法可靠提出结果时，用户可直接手工补录。

### Draft 在确认前完整可改，证据不可改

处于 `WAITING_USER` 或 `EDITED` 的 Draft 可修改经济类型、金额、时间、商户/对方、备注、业务渠道、资金账户以及投资目标。币种在本切片保持创建时币种，避免绕过来源允许币种。编辑使用独立幂等命令和审计记录；Draft ID、创建命令、创建时间、来源模式和来源证据链接不可变。已确认、已关联或已忽略 Draft 不可编辑。

### FUNDED_BY 只由用户显式确认

当一条支付宝/微信支出 Draft 与一条银行 Draft 同金额、同币种、同资金账户、同规范化商户且时间接近时，Bill 可以提出 `FUNDED_BY` 候选。用户确认后只生成一笔支出：钱包渠道描述经济事件，银行卡或信用卡账户承担真实资金腿；两条 Draft 与证据都链接到同一替代交易，银行证据不再重复计算支出。

当前候选硬门为：两条均是未关联外部支出；渠道组合必须是支付宝/微信与银行；资金账户必须一致且为银行卡或信用卡；金额币种相同；规范化商户相同；时间差不超过 30 分钟。任何门不满足都不猜测，保留为独立待审核项。电子钱包余额账户不得走该关系，符合 ADR-0009。

撤销该替代交易会原子恢复两条 Draft 到可审核状态并保留证据。`FUNDED_BY` 不自动确认，不因金额相同跨商户或跨日合并。

## 结果

- 缺通知的真实交易可由一次磁贴截图或手工补录进入同一审核流，不需要后台截图或网络 OCR。
- OCR 采集方式不再冒充支付宝/微信来源，但用户确认的业务渠道足以支持保守去重。
- 同一钱包支付与银行卡扣款能合成一笔经济支出，且两份原始证据都可追溯、可撤销。
- 代价是 Room v10、完整 Draft 编辑表单、新审计命令、候选索引与对账仓储完整性测试。

## 被否决方案

- 把所有截图直接标成支付宝或微信：证据来源失真，且语言/界面变化会造成错误归属。
- 等待所有平台都产生通知：内部支付本来就可能无通知，无法作为产品完成条件。
- 后台持续截图或轮询页面：耗电和隐私成本与本地优先边界不符。
- 仅按金额自动合并：会误合不同商户、红包、提现和同额重复消费。
- 删除银行 Draft 只保留钱包 Draft：丢失资金账户证据，也无法审计或撤销。
