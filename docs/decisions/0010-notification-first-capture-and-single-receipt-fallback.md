# ADR-0010：通知优先自动草稿与单次收款凭证补充

- 状态：已接受；通知管线、5 条默认关闭的 provider 实验 route、持久更新去重、有界队列、单次 PNG 收据分享与本地 OCR 候选已实现，通知/OCR 真机发布门仍待完成；第 5 条基金 route 受 ADR-0014 约束
- 所有者：项目维护者
- 最后核验：2026-07-31
- 事实来源：项目负责人 2026-07-25 明确需求、Android NotificationListenerService 官方文档、ADR-0003、ADR-0009、ADR-0011

## 背景

项目需要的主路径不是要求用户逐笔查账或每次开启采集，而是：当微信、支付宝、银行 App 或短信 App 显示完整的交易通知时，Bill 自动保存本地证据并创建待确认草稿。正式交易仍由用户确认，避免错误解析直接影响账本。

红包、个人转账和部分余额变动可能没有完整通知。用户接受在“已领取/已收款”结果页使用一次性截图快捷入口补充这类例外，但不接受全天截屏、录屏、轮询 OCR、Root 或把查完整账单变成日常操作。

## 决定

本决定首批交付受控通知边界、4 条默认关闭的 provider 实验 route 和单次 PNG 收据回退；后续 [ADR-0014](0014-investment-position-snapshots-and-confirmed-events.md) 在相同边界内新增第 5 条基金申购确认 route。未知 metadata、关闭 route 或正文不匹配时不持久化；命中信封只生成可证明的 CNY 金额、方向和有限事件提示，不能自动写入正式账本。用户也可通过 Sharesheet 明确提供一张 PNG，走有界结构校验、私有证据暂存与手工复核；独立的磁贴/Photo Picker OCR 候选仍受真机发布门约束。支付宝、微信和银行继续显示 `FALLBACK_REQUIRED`，窄范围实验 route 不等于完整来源支持。资源与授权预算由 [ADR-0011](0011-local-resource-budget-first-capture.md) 补充约束。

### 自动通知路径

```text
系统交易通知 / 银行短信通知
  -> NotificationListenerService（系统事件回调）
  -> 包名/具体频道/类别 + 已验证交易模板的内存过滤
  -> 持久观察租约（HMAC 摘要，恢复复用 command）
  -> 容量 16 的单消费者队列
  -> 有界私有通知证据
  -> immutable RawEvent(provider/NOTIFICATION)
  -> provider/模板 parser
  -> Draft（待确认，绝不自动正式过账）
```

- 用户显式授予通知访问后，Android 仍可能把任意 App 的回调交给 listener；Bill 只能先使用短暂包名、具体 Android 通知渠道和类别门禁，未命中即返回。它不读取历史通知、不轮询、不截屏、不录屏、不执行外部 UI 操作。
- 包名允许列表本身不足以保存正文。必须先在内存中命中已验证的交易模板；未匹配通知立即丢弃，不写文件、Room、日志或崩溃报告。这样不会把微信聊天内容当作账务证据。
- 每个真实模板要有 provider、App/系统版本范围、脱敏成功/反例样本、字段规则、幂等键和回放测试。未知格式安全停在诊断，不能用万能金额正则创造草稿。
- 当前不申请 `READ_SMS`/`RECEIVE_SMS`，也不把 Samsung 短信通知加入生产 route：其元数据无法在读取正文前区分银行短信、普通短信、OTP 和私人消息。直接 SMS 接收只能在单独政策/权限决策后研究。
- 通知到达即生成 Draft 的前提是金额、方向、完成状态和资金账户映射均足够；信息不足时生成来源待复核项或诊断，不伪造完整交易。
- listener 不得为每个 callback 启动一个协程。候选回调只复制有界字段后进入容量 16 的内存队列；满队列时丢弃这一次工作项，不写入正文、不建立后台重试或保活。持久观察记录只保存安装私有 HMAC 摘要、opaque command/lease、状态和时间；两分钟租约到期后必须复用原 command，避免进程死亡或通知更新产生第二个 RawEvent。

### 无通知收款例外

- 用户在已经领取红包、接受转账或打开收款详情后，可用 Android 正常截图，再从系统 Sharesheet 明确选择 Bill，提供一张当前单页 PNG 凭证。它不需要、也不申请相册全盘权限。
- 当前实现只接受最多 4 MiB 的 `image/png`，在当次 `content://` 临时授权中校验签名、IHDR、分块和 CRC 后存入私有证据链；不持久化 URI/文件名、不解码或预览像素、不运行 OCR。图中金额、方向、对手方、账户和 provider 一律由用户以原图为准填写。未来 OCR 结果必须另带置信度、可编辑字段、图像生命周期和真机资源证据；它不是常驻屏幕服务、后台视频流或批量查账。
- 未领取红包、未接受即退还、过期或从未进入本人余额的截图只形成非资金观察或由用户丢弃，不创建收入/退款/支出。
- 已进入余额后另行转回是两笔钱包资金变化；不能默认归类为商户退款。

## 性能与安全约束

- Notification Listener 依赖系统事件回调和包名/具体 Android 通知渠道/可选类别过滤，不能使用定时扫描、通知历史全量读取或后台 OCR。
- 单次截图只在用户显式动作后读取一张有界 PNG 流，完成或失败后擦除临时字节；当前没有图像解码、预览或 OCR 中间数据，也不保留无关屏幕内容。
- 任何通知、截图或 OCR 内容都只在应用私有存储内，遵循现有 RawEvent 不可变、保留、清除、容量和审计语义。

## 已知边界

如果一笔钱包余额变化没有通知、没有可读前台结果页、也没有用户提供一次性凭证，非 Root、无官方个人账户 API 的 Android 应用没有输入源。它必须显示为覆盖缺口，而不能由银行卡流水、余额差或历史模式伪造。

## 被否决方案

- 以全天截屏、录屏、轮询 OCR 观察支付 App：电量、隐私与可靠性成本不可接受。
- 用无障碍服务自动点击、导航、发起或确认支付：超出只读记账范围并有平台合规风险。
- 把通知缺失解释为零交易，或把钱包余额差自动补成分录：会导致漏账或虚假账。
- 一开始请求完整短信箱权限：通知入口已覆盖可见短信通知，直接 SMS 读取应是单独、明确同意的后续决策。
