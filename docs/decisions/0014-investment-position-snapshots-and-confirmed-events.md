# ADR-0014：基金持仓快照与已确认投资事件分离

- 状态：已接受
- 所有者：项目维护者
- 最后核验：2026-08-01
- 事实来源：投资产品规格、项目负责人确认的手工/OCR 方案、2026-07-31 本地私有支付宝基金通知样本

## 背景

用户需要把基金等投资纳入净资产，但支付通知通常只描述某次申请或确认，不能给出完整份额、实时价格和全部持仓。当前私有样本还表明，同一来源会分别发送“申请受理”“确认成功”和不涉及资金变化的行情提醒。若把任一通知直接当成普通支出或完整持仓，会造成资产漏记、重复记账或凭空推断。

## 决定

### 持仓快照

基金持仓由用户手工填写，或由用户主动选择一张页面截图在设备上 OCR 预填后确认。最小必填为名称和当前金额；基金代码、份额和成本可选。当前金额带 `asOf` 时间，是用户确认的估值快照，不宣称实时行情，也不从通知持续更新。

### 投资事件

申购/赎回是独立的 `INVEST_BUY/INVEST_SELL` 交易，连接资金账户和投资持仓账户，不计普通收入或支出。通知只可以提出待复核事件：

- 明确“确认成功”且格式、金额和标的均通过版本化模板时，可以提出投资草稿。
- “申请受理”、处理中、失败或取消不立即入账。
- 行情、涨幅、收益和营销提醒不是资金事件，必须拒绝。

用户选择持仓和资金账户并确认前，通知不得改变总账或持仓。

### OCR 与资源边界

持仓 OCR 是用户单次动作，使用随包模型本地执行；不增加网络、相册全盘扫描、后台轮询或常驻识别。通用支付截图 parser 继续阻断基金语义，持仓字段由独立 parser 处理，结果仅用于预填可编辑表单。

## 结果

- 用户可以在缺少份额或成本时先记录当前资产，又不会把未知值伪造成零。
- 通知与持仓页面各自承担自己能证明的事实，避免用一条通知猜完整资产。
- 申购不会被统计为日常消费；资金账户减少与投资账户增加在同币种内平衡。
- 代价是需要新增持仓实体、估值时间、投资复核 UI 和显式迁移；自动净值与完整收益分析不在本决定范围内。

## 被否决方案

- 把支付宝基金通知直接记为普通支出：会减少净资产两次并污染消费统计。
- 看到“申请受理”就立即过账：申请仍可能失败、取消或与后续确认重复。
- 根据通知金额自动创建完整持仓：通知不能证明份额、成本、价格或既有仓位。
- 放宽通用 OCR 的“基金”阻断：会让行情、红包和多金额页面误入普通收支。
- 为获得实时净值上传持仓或持续抓屏：违反本地优先和资源预算约束。
