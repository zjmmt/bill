# ADR-0013：美元只限银行卡和信用卡，且不做汇率换算

- 状态：已接受
- 所有者：项目维护者
- 最后核验：2026-07-26
- 事实来源：项目负责人 2026-07-26 的明确范围约束、ADR-0009、现有平衡分录模型

## 背景

首个账本切片固定为 CNY。项目负责人要求补充美元账户，但明确支付宝与微信支付的钱包余额不能是美元；可持有美元的仅是银行卡和信用卡。产品不提供汇率、折算或跨币种净资产总数。

## 决定

1. CNY 和 USD 是首批可创建的币种。
2. 只有 `ASSET_BANK` 与 `LIABILITY_CC` 可以创建 USD 账户；现金和电子钱包余额固定 CNY。为保持复式分录逐币种平衡，隐藏系统账户按 CNY/USD 各自建立一套；它们不能由用户创建、显示或选择，且不是用户资金账户。
3. 支付宝、微信支付及其通用截图/OCR/通知候选在第一阶段只能产生 CNY。银行适配器未来可在有明确币种证据时产生 USD，但未知币种不能默认 USD。
4. 一张草稿、一个资金账户和一笔平衡分录必须同币种；跨币种转账、换汇、汇率表、估值折算均不在本决定范围。
5. 总览分别显示 CNY 与 USD 的资产、负债和净值；UI 禁止显示把两个币种相加的“总资产”或“总净值”。
6. 手工录入与来源复核根据选定资金账户确定币种；当草稿已绑定 CNY 钱包时，不能切成 USD。

## 后果

- 新增美元银行卡/信用卡、期初余额、收入和支出可以完整走 `Draft -> confirm -> Entries`，而不会伪造汇率。
- 当前 CNY-only 的系统分类账户不能承接 USD 分录，因此需要为 USD 生成同币种的系统收入、支出和期初权益账户，或等价的显式系统账户策略；这一点必须在实现中通过平衡校验和迁移测试证明。
- 钱包来源即使有误标的外部文本，也必须失败为可见待复核/诊断，不能把 USD 写入支付宝或微信账户。
- 报表、导出、对账和未来换汇必须保持“币种不可相加”这一边界；新增换汇是独立 ADR 和账务模型工作，不能被 UI 汇总偷渡。

## 不做什么

- 不提供实时、离线或手填汇率。
- 不将 USD 折算为 CNY，也不生成跨币种损益。
- 不宣称支付宝、微信支付或任何具体银行已支持外币通知/账单；来源能力仍以样本与回放测试为准。

## 验收

- 账户创建、存储库和过账工厂都拒绝 USD 现金/钱包和所有非 CNY/USD 币种。
- USD 银行卡与信用卡可以创建期初余额、草稿和正式分录，并保持每币种平衡。
- 总览在 CNY 与 USD 同时存在时不会调用跨币种加法；界面能明确看出每项币种。
- 支付宝/微信的候选、通知与 OCR 回放测试都只产生 CNY，且不能映射到 USD 钱包。
- 旧 CNY 数据迁移不改变余额、草稿或审计记录。
