# ADR-0002：支付宝、微信支付和银行均为首期一等来源

- 状态：已接受
- 所有者：项目维护者
- 最后核验：2026-07-19
- 事实来源：项目负责人对原报告范围的明确修正

## 背景

原设计报告把 V1 定义为“支付宝优先”，微信与银行只预留通知接口。这不能满足项目实际意图，也会诱导领域模型、解析器、样本库和 UI 形成支付宝中心的技术债务。

## 决定

MVP 从第一天同时建模三类来源：支付宝、微信支付和银行。它们共用来源契约、草稿确认、账本和对账管线，并分别拥有产品规格、适配器、样本库和验收状态。

“一等”表示范围与验收同级，不表示上游平台提供同样 API 或实现同样自动化。通知可以是尽力支持，用户官方账单导入可以是正式补齐，手工录入是共同回退。

## 结果

- 正面：绑卡支付和跨来源去重从一开始就是主流程，不需后期重写核心。
- 代价：MVP 工作量高于原报告 4–6 周的支付宝原型估计；需要更多脱敏样本和 provider 管理。
- 约束：共享模块不得出现平台专属核心实体；银行必须按机构/格式逐步声明，不能用“万能银行解析器”制造虚假支持。

## 被否决方案

- 先把支付宝逻辑写进核心，未来抽象：高概率固化错误账户/外部 ID/通知假设。
- 对所有银行使用一个金额正则：无法诊断格式漂移，误入账风险不可接受。
