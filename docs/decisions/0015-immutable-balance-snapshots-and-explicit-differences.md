# ADR-0015：余额快照不可变，差异只进入待解释状态

- 状态：已接受
- 所有者：项目维护者
- 最后核验：2026-08-01
- 事实来源：MVP G-10、账户/负债/投资规格、对账设计、ADR-0009 与当前 Room v11 账本/余额快照实现

## 背景

Bill 当前能从活动分录推导账户余额，但用户无法记录“银行或钱包此刻实际显示多少”。因此应用既不能指出漏记、错绑账户或错误期初余额，也无法为月结和后续跨来源对账提供完整性证据。直接把用户输入的余额覆盖到账户表，或把差额自动记成收入/支出，会破坏分录可追溯性；钱包差额还可能被错误解释成红包、转账或消费。

## 决定

### 快照是证据，不是可变余额

用户可为现金、银行卡、电子钱包余额或信用卡记录一个不可变 `BalanceSnapshot`。快照保存账户、用户视角余额、币种、观察时间、记录时间、可选备注、来源模式和稳定命令；不修改账户余额列，也不直接创建交易。

- 资产余额按用户看到的有符号金额保存；当前切片只接受零或正数。
- 信用卡保存用户看到的正数欠款。账本内部负债仍为负，比较时才转换为用户视角。
- 投资持仓继续使用 `InvestmentPosition.currentValue/asOf`，不重复写入普通余额快照。
- 系统、归档、包装层、分类、权益和尚未接入的贷款/投资现金账户不能记录快照。

### 差异按快照时点动态计算

差异定义为：`用户快照余额 - 快照时点的账本用户视角余额`。账本侧只汇总状态为 `ACTIVE`、且 `occurredAt <= snapshot.asOf` 的分录；快照之后发生的交易不得改变历史差异，后来导入且发生在快照之前的交易、或撤销历史交易可以改变差异。

每个账户界面先显示最新一条快照和差异；历史记录保留在 Room，当前切片不提供批量删除或完整历史浏览。零差异显示“已对上”，非零差异显示带符号金额和“待解释”，不能只靠颜色表达。

### 用户确认前不制造调整

快照差异不得自动创建 `INCOME`、`EXPENSE`、`TRANSFER`、`REFUND` 或 `ADJUSTMENT`。后续对账工作台可以列出遗漏导入、错误账户、期初余额或明确调整等解释，但只有用户选择原因并预览分录后才允许生成可撤销调整。

### 幂等与完整性

创建快照与审计记录、command receipt 在同一 Room 事务中提交。同一命令和相同规范载荷重试返回同一快照；不同载荷复用命令返回碰撞。Room 观察层验证账户存在、币种一致、来源枚举、金额范围、时间顺序和 receipt 指向；损坏行使活动账本快照失败关闭。

## 结果

- 用户能看见“账本算出来的余额”和“实际看到的余额”是否一致，而不会把差额伪装成已知交易。
- 历史时点比较不受之后正常交易干扰，并会响应补录或撤销的历史事实。
- 代价是新增 Room v11 表、按账户的时点汇总查询、账户页表单和完整性测试；自动解释与调整仍是后续独立切片。

## 被否决方案

- 直接覆盖账户余额：绕过分录并丢失差异来源。
- 按当前余额比较任意历史快照：快照之后的正常交易会产生假差异。
- 自动把钱包差额记成收入或支出：违反 ADR-0009，且无法证明红包、转账或消费语义。
- 把投资估值也写入普通余额快照：会与持仓快照形成两个互相漂移的事实源。
