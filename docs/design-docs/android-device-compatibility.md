## 验收原则

- “同为 Android”不表示权限入口、后台策略、文件选择器或通知表现相同。
- “同为 S24 Ultra”不表示港版与国行固件、地区服务、安装渠道和上游 App 通知模板相同。
- 核心账本不得依赖 Google Mobile Services；是否装有或启用 GMS 是每台设备的实测字段，不由销售地区代替结论。
- 通知是 `Best effort` 入口。漏采必须表现为未知、受限或长时间未成功，而不是虚假显示“正常”；文件导入和手工录入始终可用。
- 不把“关闭全部省电保护”写成默认使用条件。若某项 OEM 设置确实影响行为，应记录最小设置、影响和回退。
- 真机证据只能使用合成数据或已脱敏数据。原始通知、账号、商户、余额和个人文件路径不得进入截图、日志或 Git。
- “物理屏幕很大”不等于 Android 的大屏分类；方向与窗口结论必须记录实际 `smallestScreenWidthDp`、当前窗口 dp 和窗口模式。

## 竖屏策略与 Android 16 边界

当前版本的 `MainActivity` 在 Manifest 请求 `android:screenOrientation="portrait"`，手机全屏竖屏是唯一主设计路径。它是方向请求，不是所有显示环境的强制保证。

项目 `targetSdk = 36`。按 Android 官方规则，Android 16 在 `smallest width >= 600dp` 的显示环境默认忽略 `screenOrientation`、`resizeableActivity`、最小/最大宽高比和 requested-orientation API；分屏、桌面窗口、虚拟设备所有者和 OEM 策略也可能改变最终窗口。详见 [Android 16 目标应用行为变更](https://developer.android.com/about/versions/16/behavior-changes-16#device-form-factors)、[方向、宽高比和可调整大小指南](https://developer.android.com/develop/adaptive-apps/guides/app-orientation-aspect-ratio-resizability) 与 [`<activity>` Manifest 文档](https://developer.android.com/guide/topics/manifest/activity-element#screen)。

本项目不使用临时的 `PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY` 退出机制：它不是长期方向保证，目标 API 37 起也不再可用。方向请求被忽略时，UI 仍须以单列、宽度受控、可滚动的布局保证所有主操作可达，并在 Activity 重建后保留遮罩、草稿编辑、导航和滚动状态；这只叫韧性兜底，不叫横屏主视觉支持。
