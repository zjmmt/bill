# UI 设计系统与首个纵向切片

- 状态：已确认，待真机与可用性验证
- 所有者：项目维护者
- 最后核验：2026-08-02
- 事实来源：产品规格、三类测试设备约束、`ui-ux-pro-max` 检索结果、馆藏视觉研究与人工筛选

本文是 Bill 的页面结构、视觉语义和首个 Compose 纵向切片的唯一事实来源。通用体验原则见 [DESIGN.md](../DESIGN.md)，Compose 状态与实现边界见 [FRONTEND.md](../FRONTEND.md)，颜色与间距令牌见 [`design-system/bill/MASTER.md`](../../design-system/bill/MASTER.md)，地区/OEM 行为和完整真机门见 [Android 设备兼容与真机验收](android-device-compatibility.md)。

## 设计结论

采用 **Material 3 交互语义 + 克制的构成主义与苏联太空时代编辑视觉**。Bill 是给个人使用的本地账本，不是企业后台：信息必须可信、可纠错，但也应有明确的视觉性格。

Material 3 在这里负责组件状态、焦点、系统栏、Sheet 和无障碍语义，不再直接决定成品长相；Compose 让同一个不可变 `UiState` 同时服务运行页面、Preview 和测试。具体色彩、几何、排版与竖屏结构以本文件和 [`MASTER.md`](../../design-system/bill/MASTER.md) 为准，两者都不会替代账务规则或 OEM 真机验证。

从设计技能检索中采用：

- 个人财务产品的清晰数字层级，但不采用企业仪表盘式卡片堆叠。
- Material 3 的语义状态、原生控件、焦点与无障碍基础。
- 构成主义的非对称网格、斜向推进、圆与直线之间的张力。
- 太空竞赛时期海报的深蓝场、轨道圆形、暖色信号和标题/技术信息层级。
- `#123B68` 作为主操作蓝；`#B92724` 只作红楔品牌信号；`#F3EBD8` 纸张、`#101D3D` 宇宙深蓝与 `#D9A326` 太阳金构成主调。
- 48dp 点击区、4/8dp 间距节奏、双主题、系统字体和克制动效。
- 趋势使用折线，分类比较使用排序条形，并提供文本/列表替代。

明确不采用：

- 玻璃拟态、霓虹渐变、纯黑交易终端风格。
- 通用后台模板、满屏同款圆角卡片和没有视觉主次的“安全蓝”。
- 每张卡都加红楔、火箭、星星、仿西里尔字或政治徽记的主题乐园式复刻。
- 超大标题泛滥、余额跳数动画和装饰性持续动画。
- 只用红绿区分收支或盈亏。
- 页面各自硬编码颜色、阴影和圆角。

## 视觉方法与来源

参考只用于提炼形式，不复制馆藏图像或政治语义：

- [MoMA 189492：Ivan Picelj，*Beat the Whites with the Red Wedge (after El Lissitzky)*，1969](https://www.moma.org/collection/works/189492)：提取红楔的方向性、几何反压与有限色板。
- [Science Museum Group co415116：*Poster of Valentina Tereshkova, First woman cosmonaut*，1963](https://collection.sciencemuseumgroup.org.uk/objects/co415116/poster-of-valentina-tereshkova-first-woman-cosmonaut)：提取肖像尺度、轨道框景与标题/技术信息分层。
- [Smithsonian A20150394000：*Into Space!*](https://airandspace.si.edu/collection-objects/space-soviet/nasm_A20150394000)：提取向上轨迹、深空冷色场与小面积暖色信号。

落地规则：阅读顺序仍是自上而下；每个视口最多一个主红楔；斜线与轨道只能位于内容边缘或背景；正文、输入框、交易行和触控区域保持水平。红楔 `#B92724` 不表示收入、支出、错误或删除，错误使用独立的 `#8E2430` 并带文字/图标，收支始终带正负号与方向文本。

## 信息架构

手机端使用四个带文字标签的一级入口：

| 入口 | 用户问题 | 首要内容 |
| --- | --- | --- |
| 总览 | 我现在的账是否健康？ | 净资产、资产/负债、待处理、来源健康、最近交易 |
| 草稿 | 哪些证据需要我判断？ | 硬阻断、疑似重复、低置信草稿、批次处理 |
| 账本 | 最终记了什么？ | 已确认交易、筛选、搜索、审计入口 |
| 账户 | 钱实际在哪里？ | 资产、负债、钱包余额、投资和余额差异 |

设置、隐私、备份和删除从顶部应用栏进入，不占用一级导航。当前版本以手机竖屏为唯一主设计基线：`MainActivity` 在 Manifest 请求 `portrait`，紧凑窗口使用单列内容与底部导航；本阶段不启用 Navigation Rail 或列表 + 详情双栏。宽窗口只做内容宽度约束、居中与安全留白，不把手机主界面改造成横向仪表盘。

## 产品文案

界面文案服务于用户判断，不承担工程进度汇报。发布版不得出现“解析器、模板、路线、回调、队列、进程、契约骨架、样本验证、重放测试、资金腿、审计链”等实现或测试术语；这些事实只进入设计文档、执行计划和测试报告。

- 标题说明“这里是什么”，正文只保留目的、直接影响和下一步；同一事实不在同一页面重复解释。
- 常驻列表页不在标题下重复讲产品规则；首次引导放在空状态，风险边界放在触发权限或确认操作的位置。
- 空状态只给一个合理入口；成功提示说明结果，错误提示说明是否写入以及如何恢复。
- 删除、权限范围、识别不确定性、币种限制和不可逆操作必须明确，但每项只保留完成决定所需的最短说明。
- 面向用户统一使用“草稿、待确认、资金账户、交易类型、交易渠道、原始资料”；内部的 `Draft`、`RawEvent`、路由和账务分录名称不直接翻译到界面。
- 工程能力是否通过样本、真机或发布门，只影响功能是否显示和状态是否可用，不作为宣传句或状态说明展示。
- 简体中文、繁体中文和英文保持相同的信息层级；本地化可以调整自然表达，但不得增加另一语言没有的权限承诺或工程说明。

首个可运行页面按以下顺序呈现：

```text

│                                              │
│ 净资产                         显示/隐藏      │
│ ¥ 24,680.00                                  │
│ 资产 ¥30,500        负债 ¥5,820              │
│                                              │
│ 待处理草稿 3 笔        [去复核]              │
│ · 1 笔资金账户未知                            │
│ · 1 组疑似重复                               │
│                                              │
│ 采集状态                                     │
│ 支付宝 可用   微信 需检查   银行 需补录        │
│                                              │
│ 最近交易                                     │
│ 午餐              -¥32.00   招商借记卡        │
│ 信用卡还款       资金移动    不计普通支出       │
└ 总览       草稿       账本       账户          ┘
```

要求：

- 默认展示合成数据；截图、Preview 和测试不得包含真实账单。
- 金额遮罩是可恢复的 UI 偏好，不改变底层账本。
- 资产与负债不能只靠绿色/红色区分，必须有文字、方向和符号。
- 没有数据时解释如何建立期初余额；来源失败时给出文件导入或手工回退。
- 总览只提供摘要，不在手机首屏堆叠多张图表。

## 草稿复核 Bottom Sheet

从“待处理草稿”进入统一 `ReviewBottomSheet`：

1. 顶部展示金额、时间、商户/对手方和明确来源徽标。
2. 展示“为什么需要确认”，例如“付款渠道已识别，但真实资金账户未知”。
3. 分开编辑经济类型、渠道与真实资金账户。
4. `ConfidenceExplanation` 用自然语言显示证据，不暴露完整通知原文。
5. 保存前展示分录影响；转账/还款明确写出“不计入普通收支”。
6. 每页只有一个主操作“确认入账”；“稍后处理”和“关联已有交易”为次操作。
7. “忽略”与主操作空间分离，并支持撤销。
8. 有未保存修改时，下滑或返回必须确认是否放弃。

## 状态模型

每个关键页面必须有显式状态：

- `Loading`：超过 300ms 显示骨架或进度，不能白屏。
- `Empty`：说明原因并提供一个合理下一步。
- `Content`：可展示部分来源失败，不能用整页成功掩盖局部问题。
- `Saving`：主按钮禁用并显示进度，防止重复提交。
- `Error`：说明发生了什么、数据是否安全、用户如何恢复。

页面不直接持有 Room/通知对象。不可变 `UiState` 向下流，`UiAction` 向上流；一次性导航由明确事件表达，不能用会重放的持久状态冒充。

## 无障碍与隐私

- 正文对比度至少 4.5:1；大字号和非文字控件至少 3:1。
- 所有点击区域至少 48x48dp，相邻区域至少留 8dp。
- TalkBack 顺序与视觉顺序一致；图标按钮有本地化描述。
- 支持系统字体放大至 200%，优先换行而不是隐藏主操作。
- 色彩不是唯一信号；金额提供正负号，状态提供文字/图标。
- 无障碍描述不得朗读完整通知正文、账号或隐藏状态下的金额。
- 进入后台时对最近任务缩略图使用安全策略，实施前在三类设备上验证。

## 动效

- 点击反馈在 100ms 内出现；微交互 150–250ms，Sheet/导航不超过 300ms。
- 只为因果和层级提供动效，不做余额跳数、装饰性脉冲或逐行入场。
- 遵守系统动画缩放/减少动态效果设置；关闭动效后功能和信息层级不变。

## 方向与窗口边界

“竖屏”是当前手机产品的主路径和 Activity 方向请求，不是跨设备的绝对锁定承诺。项目使用 `targetSdk = 36`；Android 16 对 `smallest width >= 600dp` 的大屏环境默认忽略 `screenOrientation`、可调整大小和宽高比限制，分屏、桌面窗口、虚拟设备所有者或 OEM 覆盖也可能暴露非竖屏窗口。官方边界见 [Android 16 行为变更](https://developer.android.com/about/versions/16/behavior-changes-16#device-form-factors) 与 [方向、宽高比和可调整大小指南](https://developer.android.com/develop/adaptive-apps/guides/app-orientation-aspect-ratio-resizability)。

因此：

- 手机全屏且平台接受请求时，页面保持竖屏单列主体验。
- 请求被忽略时仍使用可滚动、最大宽度受控的单列兜底；主操作、底部导航和复核内容必须可达，遮罩、草稿编辑与滚动位置不得因窗口重建丢失。
- 非竖屏、分屏和大屏只做可达性与状态保存验收，不宣称已完成横屏视觉优化。
- 不使用 `PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY` 临时回退；它不能形成长期方向保证，且后续目标 API 将移除该退出路径。

## 真机 UI 子集

完整的设备身份、地区/GMS、通知权限、后台、省电、文件入口和可执行用例只在 [Android 设备兼容与真机验收](android-device-compatibility.md) 维护。本文件不把港版 S24 Ultra、国行 S24 Ultra 或具体型号尚未知的国行小米写成“已通过”。

UI 在三台首批设备上至少验证以下子集：

- 简体中文、繁体中文、英文以及 CNY/USD 合成金额不会混淆币种或截断主信息。
- 系统亮/暗主题、目标最大字体与显示缩放、TalkBack 焦点和金额遮罩语义。
- 手势与三键导航、状态/导航栏 inset、可选显示分辨率、输入法，以及手机全屏竖屏主路径。
- 强制横向、分屏和 `sw>=600dp` 环境只验证单列兜底的内容可达、状态保存与不崩溃；本阶段不切换 Navigation Rail 或双栏。
- 最近任务与页面恢复不泄露遮罩前金额；截图证据只使用合成数据。

上述项目只有在兼容文档中记录设备构建、步骤、预期与脱敏证据后才能标为通过。两台 S24 Ultra 的结果不能互相替代；小米具体型号未建档前不能承担 HyperOS UI 或性能覆盖结论。

## 首个代码切片验收

本轮骨架至少证明：

1. Kotlin/Compose 工程能构建，领域核心不依赖 Android。
2. 总览页能够以不可变 `OverviewUiState` 渲染合成摘要、草稿、来源状态和最近交易。
3. 主题令牌集中定义，支持系统亮/暗主题与金额遮罩。
4. `MoneyText`、状态行和卡片具备语义化描述与 48dp 操作区域。
5. 至少有领域分录平衡测试和 UI 状态映射测试。
6. 通知、Room 和真实来源只建立边界骨架，不伪称已支持。

截至 2026-07-19，上述代码骨架已通过 `test lint assembleDebug`。默认英文资源及 `zh-rCN`、`zh-rHK` 资源已建立，总览与复核页包含 200% 字体 Preview；这些只证明编译期资源与预览基线存在，三类设备上的截断、字形、TalkBack、窗口与系统栏行为仍按兼容文档保持待验证。
