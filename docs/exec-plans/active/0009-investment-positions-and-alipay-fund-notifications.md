## 目的与用户可见结果

用户可以手工填写基金代码、名称和当前金额，份额与成本可选；也可以主动选择一张持仓页面截图，在设备上 OCR 预填后逐项人工确认。已经采集到的支付宝基金通知中，只有明确的申购确认成功格式可以提出 `INVEST_BUY` 待复核项；申请受理不立即入账，行情/涨幅提醒不创建资金草稿。

## 范围与非目标

包含：

- CNY 基金持仓账户、基金代码/名称、用户确认的当前金额快照、可选份额和可选成本。
- 手工创建与用户主动选图 OCR 预填；截图、OCR 原文和图片 URI 不写入持仓表。
- 简体中文、繁体中文的基金字段关键词；英文/日文只在有严格标签时预填，未知布局保持空白。
- 将支付宝“基金申购确认成功”真实样本抽象为默认关闭的严格通知 route，并只生成 `INVEST_BUY` 待复核。
- 申请受理、处理中、失败、涨幅/收益提醒失败关闭；用户确认前不修改持仓或总账。
- Room 迁移、幂等写入、分录平衡、脱敏回放、UI 与构建验证。

不包含：

- 自动登录、读取支付宝私有页面、后台轮询、全天 OCR、网络行情或自动更新净值。
- 根据通知猜测完整份额、实时市值、收益率或基金账户余额。
- 把基金申购记为普通消费，或把相同金额的受理/确认通知直接自动合并。
- 本轮没有真实样本的赎回、分红、转换、定投扣款失败、微信零钱通或银行理财模板。
- 自动确认、自动过账或无人工确认的持仓修改。

## 意外发现

- 当前 `AccountType`/`TransactionType` 已预留投资枚举，但用户创建白名单、`ReviewDraft`、`PostingFactory`、Room schema 和 Compose 表单仍只实现普通收支；枚举存在不等于投资已接入。
- 通用截图 parser 故意把“基金”列为阻断语义，防止误记普通支出。因此持仓 OCR 必须是独立的用户动作与专用预填 parser，不能放宽通用金额规则。
- 私有样本同时含“申请受理”和“确认成功”，它们是不同状态。没有稳定订单标识时，金额相同不能成为自动合并依据。
- 通知样本不能证明基金标的；因此 parser 只提出金额和 `INVEST_BUY` 语义，application、Room 完整性检查与 UI 都要求目标账户确实对应用户已确认持仓。
- 简体规则来自真实样本；繁体标题和金额/手续费标签是同一字段语义的兼容别名，目前仍按实验 route 失败关闭，不能写成独立真实样本支持声明。

## 决策日志

- 2026-08-01 - 当前金额作为有时间戳、用户确认的估值快照；份额和成本允许为空。缺字段不会阻止用户先把资产纳入总览。
- 2026-08-01 - 持仓账户与投资流水分离：持仓保存标的/快照，`INVEST_BUY/SELL` 保存资金移动；通知不得直接重写持仓表。
- 2026-08-01 - 只把明确“确认成功”的格式提升为交易候选；“受理成功”与行情提醒保持非入账。
- 2026-08-01 - OCR 仅由用户选图触发，复用单进程两线程本地引擎；不新增网络、相册全盘或常驻任务权限。

## 验证与验收

- 手工只填名称与当前金额即可保存；代码、份额、成本为空不会伪造零值。
- OCR 能预填脱敏的简中/繁中标签变体；多个候选、无标签数字或行情百分比不会被当成当前金额。
- 申购确认 route 只命中其版本化模板并提出 `INVEST_BUY`；申请受理、涨幅提醒和漂移格式不创建可过账草稿。
- 投资买入必须选择 CNY 资金账户和 CNY 持仓账户，分录在 CNY 内归零，且不增加普通支出。
- 迁移保留 v7 账本；失败或异常数据不会静默创建持仓。
- Release 仍无 `INTERNET` 权限，Debug 私有样本不进入源码、fixture、APK 或 Git。

## 幂等、回滚和恢复

- 创建持仓、创建投资草稿和确认买入都使用稳定 command receipt；同一命令重试返回同一实体，不重复开账或过账。
- v8/v9 迁移只新增表、列和索引，不回写旧交易。应用更新失败时保持旧数据库文件可恢复，不执行破坏性迁移。
- OCR 失败只清空临时 bitmap/字节并返回可操作错误；不创建半成品持仓。
- 通知解析失败保留可诊断状态，不猜事件类型；route 可在设置中独立关闭。
