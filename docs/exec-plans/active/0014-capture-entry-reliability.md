## 目的与用户可见结果

修复截图快捷采集、微信账单截图、通知监听状态和相册 OCR 导入四条真实使用路径。完成后，能够识别的内容必须进入待审核草稿；无法识别但已成功取得的图片必须建立可手工补录的空白待审核项；无法取得图片或权限异常必须给出明确反馈，不能静默失败。

## 范围与非目标

本计划包含截图及相册 OCR 的空结果回退、微信账单截图的可见反馈与草稿落地、通知监听授权后的连线状态恢复、不同图片连续导入时的证据标识冲突修复，以及覆盖真实持久化边界的回归测试。

本计划不扩展新的银行模板、不引入云端 OCR、不改变用户最终确认后才正式记账的规则，也不把识别失败内容自动确认为交易。

## 意外发现

- 现有 OCR 仪器测试只覆盖“位图识别后能否被解析”，没有经过 Room 证据生命周期和待审核草稿持久化，因此无法发现相册入口的全局冲突。
- 截图与相册入口都把 OCR 空结果提前转换为失败，虽然通用解析器本身已经支持 `NeedsUserReview(candidate = null)`，导致原本设计的手工补录回退没有真正接通。
- 通知服务连接回调再次查询系统授权；系统授权状态短暂滞后时会把已连接写成未连接，之后仅刷新授权无法恢复连接位。
- `RoomRawEventRepository` 的暂存消费集合漏掉 `PHOTO_OCR` 和 `SHARE_FILE`；生产入口已经建立租约并写入证据，Room 却把存在的租约当成冲突，因此重试新 UUID 也会稳定失败。这是相册“空库也冲突”和快捷截图无草稿的共同根因。
- 已安装的正式版与 Debug 仪器测试包签名不同，三星系统拒绝附着测试；测试包未运行且随后已卸载。为保护现有账本，本轮没有卸载正式版或改签测试包。
- 覆盖安装后通知监听授权仍在，系统服务记录显示 `requested=true`、`received=true`、`hasBound=true`；截图无障碍服务当时未授权，因此不把快捷截图入口写成已完成真机交互验收。
- v4 交付后，真实相册导入显示：已完成的提现页面因同时保留历史“处理中”步骤而丢弃了明确的 `0.01` 金额；同一张可由相册 OCR 提取 `9.90` 的支付画面通过磁贴截图时仍落入通用失败且未建草稿。前一轮自动化未覆盖这两种真实边界，计划因此重新打开。
- 私有真机探针证明随包 OCR 已能从两张新增原图分别读出预期金额；提现问题发生在 parser 状态门，而不是模型漏字。完成状态只有在具有空间边界、位于待处理状态之后且匹配精确终态时才能解除待处理门；没有边界或顺序相反时继续失败关闭。
- Android 截图 API 返回的硬件位图不能交给软件 Canvas。原实现因此在磁贴入口抛出运行时异常并被折叠为通用失败；新实现先在硬件位图上有界缩放，再复制为 `ARGB_8888` 软件位图，避免全尺寸软件副本的内存峰值。
- Debug 变体改用独立应用 ID，使仪器测试不会再与内部签名正式版发生签名冲突，也不会读写正式版账本。私有截图只在一次性测试 APK 中出现，测试后已重新组装并检查清除，不进入源码、Git 或构建产物。
- v5 的真实磁贴点击已经成功建立草稿，但用户没有看到点击或完成反馈。后台 Toast 不是可靠的唯一反馈渠道；v6 在点击时立即显示安全进度提示，并让磁贴在下次展开时持久显示“草稿已建立”或“上次未完成”，直到应用消费该回执。
- v6 真机进一步证明，折叠通知栏时的磁贴副标题和稍后返回 Bill 才出现的提示仍不是截图反馈：用户在外部页面无法判断当前一帧是否已经取得。反馈必须留在当前页面并紧跟平台截图成功回调，而不是等待 OCR、入库或应用重新前台。
- 微信聊天转账通知仅含 `[Transfer] Accept transfer`，属于尚未领取且无金额的提示；微信零钱提现的系统通知只有“发起/已到账”，金额只在微信支付详情页。当前通知 route 因此正确失败关闭，金额仍由用户触发的磁贴/选图 OCR 补充。若未来引入无金额待补项，必须单独决策其去重与账务语义。
- Android Manifest 原本声明了自适应图标，但安装标签仅为 `Bill`，Gradle 原始产物名为 `app-arm64-v8a-release.apk`，无法向小范围测试用户表达用途和身份。v6 增加与现有红楔视觉一致的兼容/自适应图标、本地化“Bill · 本地记账/本機記帳”标签，以及验签后的 `Bill-Local-Ledger-Android-arm64-v8a.apk` 交付副本。

- 2026-08-02 - 成功取得系统截图后，位图转换或本地 OCR 运行失败也属于“已取得图片但无法识别”，必须进入空白审核回退；只有截图 API 本身未取得画面时才报告截图失败。
- 2026-08-02 - Toast 只能作为即时提示，不能作为磁贴后台任务的唯一结果通道；安全结果枚举会继续留在本地回执中，并映射到磁贴副标题，不包含金额、来源、账户或 OCR 原文。
- 2026-08-02 - 截图成功回执使用专用无障碍 service 的 `TYPE_ACCESSIBILITY_OVERLAY`：只在平台成功回调之后显示 180 ms，覆盖层没有文字、截图或账务数据，不接收触摸/焦点，也不需要悬浮窗权限。它只表达“这一帧已取得”，不提前表达 OCR 或草稿成功。
- 2026-08-02 - 无金额且未完成的微信聊天转账通知不生成收入草稿；无金额提现完成通知也不猜金额。可选的“待补金额”通知项属于后续产品语义，不在本轮故障修复中偷偷扩展。

## 实施步骤

1. 为 OCR 文本契约定义可持久化的空识别结果，并让截图与相册入口共同使用。
2. 用真实 Room 仓库串联两次独立导入，定位并修复证据、原始事件或提交键的稳定标识冲突。
3. 将通知服务“已连接”与授权查询解耦，并在授权返回后提供一次受控的重新绑定恢复。
4. 为快捷截图保存不含财务内容的结果回执，并在平台截图成功后于当前页面短暂显示无内容闪屏；前者承载稍后结果，后者只证明当次截图已经发生。
5. 运行单元测试、仪器测试、静态检查与构建，再在真机按用户步骤验证。

## 验证与验收

- 无关页或无可识别文字的截图：出现明确反馈，并建立一个可编辑、金额为空的待审核项；不产生正式交易。
- 微信账单截图：无论识别成功或进入空白回退，都有用户可见结果；识别出的金额进入待审核草稿。
- 截图成功反馈：在外部页面点击磁贴并成功取得画面后，无需返回 Bill 即可看到短暂整屏闪烁；反馈不拦截触摸、不出现在已取得的截图像素中，也不把 OCR/草稿未完成误报为完成。
- 通知权限：授权后服务真实连接时状态为“已就绪”；授权回调竞态不会永久停留在“尚未连线”。
- 相册选择：空数据库连续选择不同图片不出现“与已有记录冲突”；相同内容再次选择只进入可能重复审核路径。
- 自动化测试必须穿过 OCR、证据生命周期、Room 和待审核持久化边界；最终仍需目标真机逐项确认。
- 测试日志和夹具不得包含真实账号、完整通知或用户截图。

## 幂等、回滚与恢复

所有导入继续使用不可变 `RawEvent` 和独立命令标识。中断后可重新选择图片或重新截图；重复内容不会覆盖旧证据。若新回退逻辑异常，可按入口回滚，不需要迁移既有正式交易。
