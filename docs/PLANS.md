# 执行计划规范

- 状态：已确认
- 所有者：项目维护者
- 最后核验：2026-07-19
- 事实来源：Harness Engineering 的计划即工件原则

执行计划是可恢复、可版本化的工作记录。它让没有聊天上下文的贡献者只凭仓库也能继续任务。

## 何时必须写 ExecPlan

- 跨多个模块或预计超过一个工作日的功能。
- 新增支付宝、微信或具体银行适配器。
- Room schema/备份格式迁移。
- 改变分录、去重、转账、还款或投资语义。
- 新增高风险 Android 权限、网络处理方或同步机制。
- 大型重构、性能工程、数据恢复或安全修复。

小型文案、明显局部修复可以用任务描述，但仍须满足对应文档和测试约束。

## 文件生命周期

1. 从 [TEMPLATE.md](exec-plans/TEMPLATE.md) 创建 `active/NNNN-short-name.md`。
2. 开始前填写目标、上下文、验收、恢复方案和具体命令。
3. 执行中持续更新进度、发现和决策日志；不要事后一次补写。
4. 完成后记录结果与遗留问题，移动到 `completed/`。
5. 未完成但不再继续的计划标记 `已取代/已取消`，说明原因和替代路径。

## 必备章节

- 目的与用户可见结果
- 范围与非目标
- 上下文与仓库导航
- 进度（带时间戳的复选项）
- 意外发现
- 决策日志
- 实施步骤和明确命令
- 验证与验收
- 幂等、回滚和恢复
- 结果与复盘

计划不得依赖“见之前聊天”或外部任务系统中的隐含信息。外部链接可以作为证据，但关键约束必须写入仓库。
