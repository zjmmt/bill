# 后续版本：账户维护、基金日常记录与收支图表

- 状态：已确认需求；待创建实施 ExecPlan
- 所有者：项目维护者
- 最后核验：2026-08-02
- 事实来源：项目负责人 2026-08-02 的实际使用反馈、当前账户/持仓/账本实现、ADR-0014、ADR-0015 与收支图表页规格

## 为什么需要这一版

当前版本已经能创建账户和基金持仓、保存期初金额，并能生成账本记录，但日常维护链路仍不完整：

1. 账户创建后不能修改；基金持仓也没有方便的每日估值入口。
2. 账本虽然存在 `ADJUSTMENT` 语义，但用户没有可用的调整流程。
3. 账户名称或期初金额填错后，不能修正，也不能删除或归档账户。
4. 基金持仓成本精度只有两位小数，且份额、成本、净值和当前市值之间缺少自动计算；若每日记录都要从头填写，实际不可用。
5. 已确认的收入和支出没有独立图表页，用户无法按时间直观看到变化。

这一版的目标不是扩大自动采集范围，而是让已经录入的数据可以长期维护、修正和查看。

## 版本目标与顺序

### P0：账户可维护

- 用户可以修改账户名称、备注和其他不改变账务语义的资料。
- 账户类型、币种等会影响既有分录的字段不能被静默改写；若未来允许变更，必须使用独立迁移流程并预览影响。
- 期初金额填错时，用户可以进入“修正期初金额”流程。系统必须撤销并重建原期初调整，或创建带审计记录的显式更正；不得直接覆盖已确认分录，也不得造成期初金额重复计算。
- 从未产生交易、快照、持仓或来源证据的空账户可以在二次确认后删除。
- 已有关联数据的账户默认只能归档。归档后不再出现在新交易的默认选择中，但历史账本和审计记录仍可查看。
- 若以后提供彻底删除，必须先展示受影响的交易、快照、持仓与证据，并作为单独的高风险删除流程设计，不与普通“删除账户”按钮混用。

### P0：可用的账本调整

- 在账户或账本中提供明确的“调整余额”入口，而不是只在内部保留 `ADJUSTMENT` 类型。
- 用户可以选择账户、调整日期、目标余额或变动额，并填写调整原因。
- 确认前必须展示调整后的账户余额和将生成的平衡分录。
- 确认后生成带原因、期间和审计记录的 `ADJUSTMENT`；它不计入普通收入或支出。
- 调整可以撤销，撤销通过作废/反向记录完成，不直接修改或删除原始证据和历史分录。
- 余额快照存在差异时可以跳转到该流程，但系统不得因为差异自动记收入、支出或调整。

### P0：基金每日估值与增量录入

- 每个基金持仓提供“记录今日估值”入口，并保留按时间排列的估值历史。
- 新记录默认继承上一次的基金名称、代码、份额、总成本和币种。用户只需填写日期以及本次变化的字段，不能要求每天从头录入整份持仓。
- 用户可以输入“当前总市值”，也可以在份额已知时输入“单位净值”，由系统计算当前总市值；两者同时输入时必须校验差异并要求用户确认。
- 单纯记录市值变化只形成不可变的持仓估值快照，不产生现金流，不记为普通收入或支出，也不改写历史快照。
- 申购、赎回等真实资金事件仍通过 `INVEST_BUY`、`INVEST_SELL` 处理，并与每日估值分开。
- 首版不联网获取净值，不后台轮询行情；用户手填或本地 OCR 预填后确认。

### P0：基金精度与自动计算

- “总成本”继续按货币最小单位保存；“份额”“单位净值”“平均单位成本”必须使用十进制定点数，不能共用只有两位小数的货币字段，也不能使用二进制浮点数。
- 单位净值和平均单位成本至少支持 6 位小数；份额至少支持 8 位小数。界面可以按有效位简化显示，但编辑时不得丢失已保存精度。
- 当份额和总成本存在时，自动计算平均单位成本：`总成本 / 份额`。
- 当份额和单位净值存在时，自动计算当前总市值：`份额 × 单位净值`；只在转成货币金额的边界按币种规则舍入。
- 当当前总市值和总成本存在时，自动计算未实现盈亏及收益率；缺少必要字段时显示“资料不完整”，不得用零值代替未知值。
- 申购或赎回确认后自动带出原份额和原成本，并按实施前确认的成本法更新。首版成本法必须在界面和测试中固定说明，不能静默切换。

### P1：独立收支图表页

- 增加独立“图表”页面，展示所选时间范围的收入、支出、收支差额和时间趋势，并提供等价的文字摘要。
- 图表只使用已经由用户确认并进入正式账本的交易。草稿、OCR 临时结果、原始通知和被忽略内容不得进入统计。
- 本人账户转账、信用卡还款、基金申购/赎回和账本调整不计作普通收入或支出；`FUNDED_BY` 只统计一次实际消费，退款按既有关系冲减原支出。
- CNY 与 USD 分开汇总和绘制，不换算、不生成跨币种总额。
- 全部聚合在本机完成，不新增网络、遥测或云端分析；金额遵守全局隐藏状态。
- 分类统计须等待稳定的分类字段和编辑体验；没有可靠分类时不伪造分类饼图。
- 完整数据口径、无障碍与图表库约束以 [收支图表页规格](analytics-charts.md) 为准。

## 共同账务与数据边界

- `RawEvent` 和已经确认的历史分录保持不可变；修改操作通过新版本、撤销、归档或显式更正表达。
- 所有会影响余额的动作必须生成平衡分录，并记录用户操作审计。
- 基金估值变化与基金资金交易是两类事件：前者描述某时点价值，后者描述现金或资产实际移动。
- 账户归档、调整、估值历史和图表统计必须按币种隔离；本版本仍不提供汇率换算。
- 不新增服务器、联网行情、遥测或读取其他 App 私有目录。

## 用户可验收结果

1. 创建一个账户后可以改名；改名后历史交易仍属于同一账户。
2. 期初金额填错可以修正，修正前后净资产只反映一次正确期初金额，并能查看更正记录。
3. 空账户可以删除；已有流水的账户会被明确归档，历史数据不会消失。
4. 用户能从账户或余额差异进入调整流程，预览并确认平衡分录；调整不污染收支统计，且可以撤销。
5. 基金第二天录入时会自动带出昨日资料，用户只改日期和市值或净值即可保存新的估值快照。
6. 输入高精度份额与成本后，平均单位成本、当前市值、未实现盈亏和收益率自动计算，保存再打开不丢精度。
7. 图表页能正确排除转账、还款、申赎、调整和重复资金腿，并分别展示 CNY、USD 的已确认收支。
8. 升级后现有账户、期初调整、持仓和账本记录保持可读；迁移失败时不得破坏原数据库。
