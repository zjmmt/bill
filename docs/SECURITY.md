# 安全、隐私与权限模型

- 状态：部分实现；通用显式文本与单次 PNG 收据证据、空模板通知边界、持久观察去重、逐项载荷生命周期与租约暂存已加固；单次截图/Photo Picker OCR 只有未通过隐私发布门的原型，发布级威胁模型和全量删除未完成
- 所有者：项目维护者
- 最后核验：2026-07-26
- 事实来源：本地优先承诺、Android 平台边界、当前 Manifest/来源证据实现、ADR-0006、ADR-0007、ADR-0008、ADR-0009、ADR-0010、ADR-0011、ADR-0012

## 保护目标

优先保护交易明细、账户标识、余额、通知原文、导入文件、规则推断、备份和加密密钥。项目不保存支付密码、验证码、会话令牌或银行卡完整号码。

## 信任边界

- 可信：应用签名下的私有进程、应用私有存储、经验证的本地数据库代码。
- 条件可信：Android Keystore、系统通知监听、Storage Access Framework 的授权机制。
- 不可信：通知文本、任意导入/分享内容、文件名/MIME、外部 Intent、外部存储、剪贴板、第三方 App、备份目的地。Sharesheet 是产品上的显式入口，不提供发送 App 或用户手势的密码学证明。
- 默认不存在的可信方：项目方服务器。引入任何远程处理都需要新的 ADR、明确同意和删除协议。

## 数据处理规则

| 数据 | 默认存放 | 保留策略 | 禁止行为 |
| --- | --- | --- | --- |
| 通用显式文本证据（分享或 SAF 选择文件） | `noBackupFilesDir` 下的应用私有文件；当前无应用层加密 | 默认 30 天；可选 7/30/90 天或永久，逐项清除；已提交与暂存载荷共用 16 MiB/512 份预算 | 写入日志/崩溃报告、公共目录或 UI 原文摘要；持久化 SAF URI/原文件名；自动删除待复核或活动暂存载荷 |
| 用户显式分享的一张 PNG 收据截图（Sharesheet 路径） | `noBackupFilesDir` 下的应用私有文件；读取期间仅有当次 `content://` 临时授权和有界内存副本 | 与其他来源证据共用默认 30 天、可选 7/30/90 天或永久、逐项清除和 16 MiB/512 份预算 | 持久化 URI/原文件名、申请相册/媒体库权限、解码或预览像素、OCR、把图中文字写入日志/崩溃报告、自动推断金额/来源/账户 |
| 用户点击磁贴截图或在 Photo Picker 选择的一张图片的 OCR 转录（开发原型） | 原始截图/Bitmap 只作瞬时输入；有界、版本化 UTF-8 转录进入 `noBackupFilesDir` 私有证据链 | 与其他来源证据共用默认 30 天、可选 7/30/90 天或永久、逐项清除和 16 MiB/512 份预算 | 持久化原始截图、URI/原文件名、相册广泛读取、节点/窗口文本、后台捕获、上传转录/像素；在替换 OCR 引擎和审计通过前将它宣传为纯本地无遥测能力 |
| 已命中合成/未来验证模板的通知信封 | 应用私有 `noBackupFilesDir` 证据链；不保存包名、通知 key、actions、URI 或 Android 对象 | 与其他来源证据共用 7/30/90 天或永久、16 MiB/512 份预算和逐项清除；生产模板目录当前为空 | 未命中元数据时读取 `extras`；持久化包名/key/正文到日志、崩溃报告或学习队列；从通知历史补采 |

| 结构化导入文件（未来） | 临时私有区或流式读取 | 完成并验证后可删除原文件副本 | 复制到公共目录 |
| 账本/规则 | Room/SQLite 私有区 | 用户主动删除前保留 | 未同意上传 |
| 备份 | 用户选择位置，应用层加密 | 用户控制 | 明文导出为默认选项 |
| 测试夹具 | 仓库 | 长期 | 含真实账号、商户组合或通知原文 |

当前 Android 首片在应用离开前台时设置窗口 `FLAG_SECURE`、重新遮罩金额，并覆盖一个不读取账户、商户、备注或金额的整页隐私帘；回到前台后才恢复账本界面。这是最近任务缩略图与后台切换的基础防线，不替代数据库加密、设备锁屏或后续威胁模型。

当前分享文本入口只接受 `ACTION_SEND` + `text/plain`；SAF 入口只接受用户当次选择的 `content://`、`text/plain`、CSV 或 TSV。两者均先做有界读取，再以严格 UTF-8 检查 64 KiB 字节上限。另一个 Sharesheet 路径只接受当次 `content://`、声明和 `ContentResolver` 解析后均为 `image/png` 的单张图片，最多复制 4 MiB，并在不解码像素的前提下校验 PNG 签名、头信息、分块与 CRC。所有 URI 只在读取边界使用，不调用持久 URI 授权，也不保存 URI/原文件名；图片临时字节在暂存完成或失败后擦除。证据使用 opaque 文件名、原子写入和 SHA-256 读取校验。错误只暴露封闭诊断和修复动作，不回显正文或图像内容。Manifest 设置 `allowBackup=false` 与 `usesCleartextTraffic=false`，当前应用不声明网络或危险权限。这些措施不等于证据已应用层加密。

开发中的 Quick Settings/Photo Picker OCR 是独立于 Sharesheet PNG 的路径：专用无障碍 service 只在用户点磁贴后调用一次 `takeScreenshot`，`canRetrieveWindowContent=false`、无手势、无目标包/窗口读取；Photo Picker 只取得用户选中的一张图片。两条路径将原始像素作为瞬时输入，仅把有界 OCR 转录接入既有私有证据链。当前运行时是 Chinese ML Kit 原型；由于其官方数据披露与 merged Manifest 组件审计均未满足本项目无遥测发布门，这条路径必须显著标为开发实验，替换引擎和 release APK 审计前不得以“纯本地 OCR”对外承诺。

通知服务是另一条边界：它不调用 `getActiveNotifications()`，不读 history、不取消/点击外部通知、不启动 UI、前台服务、周期任务或唤醒锁。生产目录为空时，它不读取正文；测试也覆盖了空目录、不匹配 metadata 和关闭 runtime 不调用正文读取器。未来命中模板的正文最多进入容量 16 的内存队列，只有单个 IO consumer；满队列直接丢弃，不能变成无限协程或后台重试。观察去重在证据前取得独立租约，进程死亡恢复时复用 command。已匹配的信封在应用内仍只进入待复核链，不能直接正式入账。首次启动和设置页明确声明本地、不走网络，并把通知、未来读屏和未来单次截图权限拆开说明；当前教程不直接引导授权未开放的能力。

载荷清除采用两阶段状态：Room 先提交 `CLEAR_PENDING`、command receipt 和请求审计，再删除精确 opaque payload 文件，最后提交 `CLEARED` 与完成审计。失败保持可重试，不把仍存在的文件谎报为已清除。自动保留和容量清理只选择没有待复核建议的证据；用户逐项清除会明确提示不可恢复，并保留 RawEvent、解析、已完成 Draft provenance 和账本审计。

Room v5 在文件写入前登记不含原文的 5 分钟租约，RawEvent 事务必须匹配并原子消费该登记。恢复任务只用 CAS 接管到期租约，再删除精确 payload 文件；活动、可用和待清除载荷受保护，`CLEARED` 的异常残留允许回收。v4 遗留孤儿只扫描至少 10 分钟前的文件，且单轮最多检查 4096 个目录项、认领 512 个 payload；扫描或数据库 ID 集合截断时安全拒绝新分享。陈旧租约和文件碰撞都不得删除另一请求的文件。

## 权限策略

- 通知访问：系统授权后仍必须命中已验证的包名、具体 Android 通知渠道和可选类别模板；禁止包级通配。生产目录当前为空，未命中项不读取正文。未来有模板后提供暂停和清除已采集证据的入口。
- 通知发送：只用于待确认、导入结果和安全提醒；拒绝后核心账本仍可用。
- 文件：通过 SAF 由用户逐次选择；不申请广泛存储访问、不持久化 URI/原文件名。
- 分享文本：通过 exported Activity 接收外部 Intent；不信任发送方、MIME 声明或正文，不推断 provider，不自动过账。
- 收据截图（Sharesheet）：通过同一 exported Activity 接收一次系统 Sharesheet `image/png`；不信任发送方或声明 MIME，要求 `ContentResolver` 再确认类型，读取后不保留 URI/原文件名或临时字节，不申请 Photo Picker/相册权限，不解码、预览或 OCR，也不自动过账。
- 悬浮窗：非 MVP 默认路径；如未来提供，必须独立开关和解释。
- 无障碍：当前有一个专用、用户可撤销的单次截图 service，声明 `canTakeScreenshot=true` 与 `canRetrieveWindowContent=false`，不读取页面节点、包名、窗口标题或事件文字，不执行手势、点击或滚动；它仅响应用户点磁贴后的单一请求。该开发原型的 OCR 运行时尚未通过无遥测发布门。未来若研究被动读取结果页，必须另用最小事件/包名范围、明确同意和本地处理的 service；不得顺带取得截图、录屏、轮询、自动点击、发起交易或在非目标页面提取内容。任何实验版本都必须先完成政策、最小用途、耗电和风险评审。
- 短信/通话记录：Play 主线不申请；银行短信解析只能作为单独研究，不得偷偷降级启用。
- 网络：核心功能不需要网络。未来价格更新或可选同步必须按域名、用途和数据类别披露。

## 加密与密钥

- 备份在离开应用私有目录前加密；密钥材料由 Android Keystore 包装。
- 备份格式必须版本化、认证加密并能检测篡改。
- 设备锁屏、Keystore 失效、恢复到新设备和用户忘记口令都要有明确失败语义。
- 不承诺“数据库加密”直到选型、密钥生命周期和性能测试均完成；当前必须依赖应用沙盒并把增强加密列为实施门。

## 日志与诊断

允许记录：随机事件 ID、来源类型、适配器版本、规则 ID、耗时、错误码、字段是否存在。

禁止记录：金额、商户、备注、通知正文、文件行、完整时间线、账号尾号组合、路径中的个人名称。

用户导出的诊断包必须先预览，默认只含结构信息，并通过自动敏感模式扫描。

## 删除与导出

- 设置页已实现单个来源原始载荷清除和保留期限；它不会删除 RawEvent、ParseAttempt、已完成 Draft provenance、审计或正式账本。若证据仍在待复核区，清除请求会同时 dismiss 对应建议。
- “全部账本/整个本地数据库”删除仍未实现；该能力必须与备份、导出、恢复和已清除载荷语义一起设计，不能用逐项载荷按钮冒充。
- 删除界面明确说明已加密备份和用户自行复制的文件不会被自动远程删除。
- 数据导出区分“可再次导入的完整加密备份”和“供用户阅读的脱敏/明文表格”。
- 当前 v3→v4→v5、两阶段失败/重试、租约恢复、磁盘数据库重开、已完成 provenance 保留与损坏状态失败关闭已有自动化；全量删除、真实系统强杀切点矩阵、压力和备份恢复仍须补测试。
- 通用分享入口不得宣传为无限量导入。16 MiB/512 份覆盖 Room 已知的已提交与暂存载荷；有界遗留扫描会在无法证明目录已收敛时拒绝新输入，但这仍不是对任意文件系统状态的绝对磁盘证明。

## 上线前安全门

1. 完成数据流威胁模型和权限清单。
2. 对不可信文件解析做大小、编码、列数、行数、压缩炸弹和公式注入限制。
3. 证明生产日志与崩溃上报不含财务数据；默认关闭第三方分析。
4. 完成备份篡改、错误口令、Keystore 失效和恢复中断测试。
5. 对每个数据源记录用户授权、平台政策、失败回退和删除行为。
6. 为分享证据补大量恶意 Intent 压力和真实系统强杀切点矩阵；复核 exported Activity、Room v5 租约 API 与删除所有权边界。

任何高风险权限、云同步或第三方 SDK 变更都必须新增 ADR 与独立执行计划。
